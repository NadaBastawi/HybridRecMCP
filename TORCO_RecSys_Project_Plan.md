# HybridRecMCP — implemented project plan and roadmap

This document replaces an aspirational plan that mixed planned folders, unverified
metrics and invented business outcomes with implemented features. Version 2 remains
Nada Bastawi's independent, unofficial synthetic-data portfolio proof of concept.

## Implemented local lifecycle

1. Fixed-window chronological synthetic generation, shared regional configuration,
   catalog suitability, exact visit gaps and quality checks.
2. Repaired original EDA notebook: correct data paths, duplicate sections removed,
   stale outputs cleared, conclusions qualified as simulation observations.
3. One-hot content features, missing-aware iterative SVD, separate gradient-boosted
   illustrative priority, explicit eligibility/repeat policies and profile cold start.
4. Global temporal training/validation/test, reserved cold customers, validation-only
   model selection, correctly named ranking metrics and separate urgency baselines.
5. Versioned trusted artifact, authenticated/validated FastAPI endpoints and health.
6. Official-SDK MCP stdio bridge with three tested tools and authenticated HTTP.
7. Actual-feature rotating logs with PSI/KS diagnostics and insufficient-data status.
8. Local Streamlit presentation, API/model/protocol/UI/data regression tests and CI.
9. Accurate README, model/data cards, audit, proposal and 3–5 minute presentation.

The architecture file lists the actual repository layout. All measurements are in
`reports/evaluation.json`; there is no claim that synthetic results predict real-world
service needs or that a company has adopted this system. See the validation report for
checks actually run and external deployment limitations.

## Deliberate scope

Default public scenario is Tucson. Ohio is a separate illustrative configuration,
not a claim of shared company ownership. All prices and numeric domain rules are
assumptions. No company logo, real customer records, booking system, treatment decision,
computer-vision module, production rollout or customer outreach is implemented.

## Pilot prerequisites and future work

- Confirm organization/use case; obtain explicit authorization and domain review.
- Secure consented representative data, approved service catalog and retention/access rules.
- Define expert relevance/priority labels and staff outcomes rather than reuse simulator targets.
- Evaluate multiple temporal folds/seeds, uncertainty, segment performance and alternative algorithms.
- Add pilot-grade identity, request limits, managed artifacts, training-reference telemetry
  and staged rollback before any customer-facing use.
- Compare against existing staff practice and measure outcomes before making business claims.

Quarterly retraining, specific percentage revenue improvements, “next 30 days” need
predictions and latent-factor stories are not asserted; they require actual evidence.
